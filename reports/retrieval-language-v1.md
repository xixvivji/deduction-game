# 게임 동의어·표현 검색 보완 실측

## 구현 범위

벡터 DB·임베딩·외부 API를 사용하지 않는 게임 도메인 어휘 검색 보완이다. `game/search_language.py`의 9개 검색 개념(진술 일관성, 행적, 목격, 보호, 정체, 추방, 공격, 추적, 시체)을 질문과 기록에 동일하게 적용한다. 예를 들어 거짓말과 진술 모순은 관련 기록으로 검색하되, 모순이 곧 거짓말이라는 사실 판정은 하지 않는다.

`game/memory.py`는 원래 어휘 점수에 개념 일치 점수를 더하고 구조화 이벤트 유형도 검색에 반영한다. 참가자 ID는 분해하지 않아 p10에서 p1이라는 두 글자 조각이 생기지 않는다. 원문과 부정 표현은 그대로 보존하며, `scoped`와 MCP capability가 먼저 참가자 권한을 제한한다. 고정 보존·최근 기록 포함과 기존 주장 검증은 유지한다. 정규식은 프로세스에서 한 번 컴파일하고 기존 토큰화 캐시의 크기 제한을 유지한다. 캐시 키는 검색 버전·방·참가자별로 분리한다. 캐시는 여전히 기본 비활성이다.

## 같은 입력 비교

공개 가능한 합성 기록 33개와 권한 밖 기록 1개, 질문 24개를 사용했다. 권한 밖 기록은 검색 전에 제외한다. 등록된 표현 18개, 원문 단어를 그대로 쓴 대조군 3개, 의도적으로 등록하지 않은 표현 3개로 나눴다. 동일 입력에서 순수 순위만 비교했으며 중요 기록 고정 보존과 최근 기록 자동 포함을 제외했다. 전은 기존 데이터 필드만의 어휘 점수, 후는 이벤트 유형·ID 처리·검색 개념을 함께 추가한 결과다. 동의어 규칙만의 단독 효과가 아니다.

| 첫 번째 검색 결과에 목표 기록 포함 | 전 | 후 |
|---|---:|---:|
| 등록 표현 18개 | 1/18 | 18/18 |
| 원문 표현 대조군 3개 | 3/3 | 3/3 |
| 사전에 없는 표현 3개 | 0/3 | 0/3 |
| 전체 24개 | 4/24 | 21/24 |

평균 검색 순위 계산 시간은 0.167ms에서 0.492ms로 증가했다. 각 질문·조건을 30회 반복한 평균이며 캐시는 껐다. 이 시간에는 MCP 왕복, 모델 생성, 웹 응답 시간은 포함되지 않는다. 추가 모델 API 호출은 없다. [전체 집계와 질문별 순위](retrieval-language-v1.json)에 Hit@1/3/8, MRR과 실행 시간을 보관한다.

## 한계와 다음 평가

- 사전에 맞춰 작성한 기능 확인용 고정 세트이며 독립 holdout이 아니다. 일반 의미 검색 성능이나 실제 게임 승률로 해석하지 않는다.
- 등록하지 않은 바꿔 말하기 3개는 전후 모두 놓쳤다. 임의의 의미 유사 문장을 이해하는 임베딩 기반 검색은 구현하지 않았다.
- 관련 개념을 묶으면 불필요한 기록이 함께 검색될 수 있다. 부정·반어·시간 순서의 의미를 검색 규칙이 판단하지 않으며, 원문을 보존해 후속 검증에 전달한다.
- 기존 `release-evaluation-v1`의 LLM 판단 실측은 이 변경 전 코드에서 얻은 별도 결과다. 이번에는 API 생성 품질을 재평가하지 않았다.
- 다음 단계에서는 사전을 보지 않고 작성한 질문과 헷갈리는 기록을 늘려 Recall@k·순위·지연을 확인한 후, 임베딩 검색과 결합하는 효과를 비교해야 한다.

```sh
.venv/bin/python -m game.evaluate_retrieval_language
.venv/bin/python -m unittest discover -s tests -p 'test_retrieval_language.py'
```

전체 Python 회귀 테스트 152개 통과. 신규 9개는 표현 검색, 부정 원문 보존, ID 혼동 방지, 부분 문자열 오탐, 캐시 분리, 로컬·실제 stdio MCP 권한 및 구조화 이벤트 검색을 확인한다.
