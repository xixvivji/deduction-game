# 서버 행동 완료·동시 실행 비교

G075 김지원 · 밤의 증언 · 2026-10-21

## 무엇을 바꿨는가

생성 성공과 실제 게임 반영·저장 성공을 분리했다. 대기열 진입부터 DB 저장까지 단계별 시간, 완료율, 실패·취소 구간, 기본 행동 비율과 확인 가능한 토큰을 기록한다. 실제 서버 설정은 유지하고, 비교에서는 동시 실행 수만 1에서 2로 변경했다.

## 실험 조건

동일한 4개 방·동일한 관측·규칙봇 출력, 생성마다 40ms 인위적 대기, 로컬 기억 검색, 실제 LangGraph와 게임 규칙 검사 및 임시 SQLite 저장. 각각 3회, 매회 새 프로세스를 사용하고 실행 순서를 번갈아 진행했다. 서버/클라이언트 초기화는 시간에서 제외한다. API 호출 0회. 아래 수치는 **합성 부하 실험이며 실제 모델 응답 속도 개선 수치가 아니다**.

입력 해시와 적용 행동 해시가 모든 실행에서 일치했다. 원시 결과는 [JSON](action-runtime-v1.json)에 보존했다.

| 지표 | 동시 실행 1 | 동시 실행 2 |
|---|---:|---:|
| 4건 전체 완료 시간 · 3회 중앙값 | 202.64 ms | 103.50 ms |
| 행동 P95 · 각 4건 P95의 3회 중앙값 | 202.46 ms | 103.30 ms |
| 평균 큐 대기 · 3회 중앙값 | 75.21 ms | 26.16 ms |
| 게임 적용·저장 완료 | 12/12 | 12/12 |
| 프로세스 최대 RSS · 3회 중앙값 | 107.12 MiB | 107.38 MiB |

## 해석과 한계

이 합성 작업에서는 동시에 처리할 수 있는 생성 대기를 겹치면서 전체 완료 시간이 약 48.9% 줄었다. 단일 모델 호출 자체가 빨라진 결과가 아니다. 4건의 P95는 최댓값이며 운영 백분위 추정에 충분한 표본이 아니다. RSS 차이는 작은 프로세스 변동을 포함하므로 메모리 절감·증가 효과로 일반화하지 않는다.

실제 API의 지연·요금·속도 제한, MCP 직렬 처리, 브라우저 표시 지연, 실제 모델의 수정 성공률은 이 실험으로 검증되지 않았다. 해당 비교는 모델 품질을 유지한 최적화의 증거가 아니라 **동일한 합성 작업에서 대기 병목을 줄이는 구조를 검증한 결과**다. 운영 대시보드와 별도 실험으로 구분한다.

## 검증 방법

```sh
.venv/bin/python -m unittest tests.test_action_telemetry
.venv/bin/python -m game.benchmark_actions
```

실제 서버 행동 경로에서 생성 후 규칙 거부, 저장 실패, 큐 시간 초과, 실행 중 취소 후 사용량 보존, MCP 검색 실패, fallback 반영을 검사한다. 기존 전체 테스트에서 실제 MCP 연결, 서버 재시작·재개, 취소 시 자원 정리도 함께 확인한다.
