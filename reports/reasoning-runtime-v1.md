# AI 근거·의심 기억·문맥 예산 검증

2026-10-21. 개발 중 발견한 오류를 재현하는 합성 회귀 테스트와 소규모 실제 API 확인이다. 독립적인 미사용 평가셋·게임 승률 평가가 아니다. 발표자료와 대본은 수정하지 않았다.

## 이전 코드와 동일 입력 비교

이전 커밋 `b01e3f8`의 game 디렉터리를 임시 디렉터리에 읽어 동일 테스트 8개를 실행했다. 사용자 브랜치는 변경하지 않았다. 새 API 호출 없이 코드의 검증·기억 동작만 비교한다.

| 조건 | 통과 | 실패 |
| --- | ---: | ---: |
| 이전 코드 | 1/8 | 7 |
| 개선 코드 | 8/8 | 0 |

실패했던 사례는 의견으로 위장한 공격/진영 단정, 잡담을 의심 근거로 사용, 검시 역할 누락의 시민 오판, 오래된 목격의 현재 의심 사용, 의심 만료 누락, 부적절한 근거의 개인 기억 저장이다. 일반 질문·불확실성 표현 유지 사례도 포함했다. 개선에 사용한 사례이므로 이 수치를 일반적인 사실 검증 정확도로 해석하면 안 된다.

## 문맥 예산 오프라인 측정

7명·500자 이내 합성 발언 70개와 조사 1개를 검색한 결과에 **12,000바이트로 설정한 예산**을 적용했다. 운영 기본값은 32,768바이트다. 관측은 14,881 → 11,023바이트, 선택 기록은 12 → 9개다. 필수 조사 기록을 보존했고 남긴 이벤트의 원문은 동일했다.

50회 적용에서 예산 처리 자체 평균 0.132ms, p95 0.152ms였다. 기존 검색·LLM 지연은 포함하지 않는다. 추가 복사/정렬 비용이며 RAM·RSS 절감 측정이 아니다.

## 실제 API 확인

기존 설정의 `gpt-4.1-mini`와 실제 stdio MCP를 사용했다. 아래 6개 입력을 각각 한 번 실행했고 기대 투표/기권 또는 날짜 있는 위치 설명 6/6을 확인했다. 다른 사람의 고발 사례는 2회 근거 검증 실패 후 3번째 생성에서 기권했다. 생성 응답을 기대 정답과 대조했으며 별도 평가 LLM은 사용하지 않았다.

| 사례 | 기대 결과 일치 | 생성 횟수 | 지연(초) | 입력 토큰 | 출력 토큰 |
| --- | --- | ---: | ---: | ---: | ---: |
| 잡담만 존재 | 통과 | 1 | 1.479 | 1,957 | 43 |
| 오래된 위치 목격 | 통과 | 1 | 1.121 | 2,120 | 51 |
| 늑대 확인 조사 | 통과 | 1 | 1.129 | 2,054 | 54 |
| 기존 의심 뒤 시민 조사 | 통과 | 1 | 1.161 | 2,149 | 71 |
| 다른 사람의 근거 없는 고발 | 통과 | 3 | 31.831 | 5,954 | 220 |
| 과거 위치의 일차·탐색 초 설명 | 통과 | 1 | 1.513 | 2,499 | 72 |

긴 입력 한 건은 같은 개선 코드에서 문맥 예산만 넉넉하게(262,144바이트) / 제한하여(12,000바이트) 각각 한 번 실행했다. 두 경우 모두 확인된 늑대에게 투표했고 기본 행동 대체는 없었다. 과거 커밋과의 실제 모델 비교는 아니다.

| 항목 | 넉넉한 예산 | 제한 예산 |
| --- | ---: | ---: |
| observation 바이트 | 16,642 | 11,481 |
| API 입력 토큰 | 5,551 | 4,279 |
| API 출력 토큰 | 56 | 58 |
| 판단 지연(초) | 1.378 | 1.319 |

입력 토큰 감소는 약 22.9%다. 전체 8회 판단에 모델 생성 10회가 발생했다. 알려진 토큰만 합계에 사용하며 실제 청구 금액은 측정하지 않았다. 반복·순서 교대·통계 검증을 하지 않아 지연 개선이나 전체 게임 비용 절감률을 주장하지 않는다. 고발 사례의 31.831초 중 두 번째 API 응답이 29.346초였으며 고정 재시도 대기는 0초였다. 검증 강화의 추가 호출 부담과 API 지연 변동을 구분해야 한다.

## 한계와 재현

- 사실 문장 검사는 제한된 한국어 패턴이다. 모든 우회 표현을 검출하지 못하고 인용/전언을 과도하게 수정할 수 있다.
- 직접 목격은 약한 정황이며 범행 증거가 아니다. 발언만으로 추론한 의심을 인증하지 않아 전략의 자유도가 줄 수 있다.
- 바이트 예산은 입력 일부를 제외하므로 일반 토론 문맥을 잃을 수 있다. 필수 근거만으로 초과하면 자동 진행보다 일시 중지를 선택한다.
- 임베딩·벡터 DB, 독립적인 사람 검수 평가셋, 누적 토큰/금액 하드 한도는 추가하지 않았다.

```sh
.venv/bin/python -m game.evaluate_reasoning_runtime
.venv/bin/python -m game.evaluate_reasoning_runtime --live
.venv/bin/python -m unittest discover -s tests
```

공개 자료는 [오프라인 집계](reasoning-runtime-v1.json), [실제 API 집계](reasoning-runtime-live-v1.json)다. 합성 원문·개별 모델 응답·상세 audit는 Git에서 제외한 `runtime/verification`에만 저장한다. 실제 사용자 게임이나 API 키는 보고서에 포함하지 않는다.

평가 설계 참고: [OpenAI 공식 평가 가이드](https://developers.openai.com/api/docs/guides/evaluation-best-practices#design-your-eval-process)의 목표·입력·평가 지표 구분을 참고했다. 여기의 소수 개발 사례가 미사용 평가셋이나 사람 검수를 대체하는 것은 아니다.
