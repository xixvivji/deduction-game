# 운영 화면과 MLflow

G075 김지원 · 밤의 증언

## 실행

게임 서버를 실행한 뒤 [운영 모니터](http://127.0.0.1:8200/ops)를 연다. 별도 프런트엔드 빌드는 필요 없다. `/api/ops`는 읽기 전용이며 3초마다 갱신한다. 원격 주소, 다른 Origin, 전달 프록시 헤더를 거부한다. 기본 가상환경 모드는 개인 로컬 운영용이다. [Docker 구성](docker.md)은 전달된 클라이언트 IP 대신 별도 운영 접근 키를 확인하며, 여전히 호스트 포트는 로컬에만 공개한다. 인터넷 공개 운영용 사용자 인증·권한 관리는 구현하지 않았다.

```sh
./run_web.sh
```

MLflow는 게임 환경과 분리한다. 아래 Python 3.12 환경이 필요하며, 패키지 버전은 `requirements-mlflow-lock.txt`에 고정했다.

```sh
uv venv --python 3.12 runtime/mlflow-venv
uv pip install --python runtime/mlflow-venv/bin/python -r requirements-mlflow-lock.txt
./run_mlflow.sh
```

`.env`에 `GAME_MLFLOW_TRACKING_URI=http://127.0.0.1:5500`을 설정하고 게임 서버를 재시작하면 운영 지표를 기록한다. 값을 비우거나 생략하면 MLflow 전송을 끈다. 서버는 `127.0.0.1:5500`에 바인딩하며 메타데이터는 `runtime/mlflow/tracking.db`에 저장한다. API 키는 필요하지 않다. 게임의 OpenAI 키는 기존 `.env`에서만 관리한다.

[MLflow](http://127.0.0.1:5500)에서 `Model training`의 `Runs`를 선택하면 숫자 지표를 볼 수 있다. 이 UI 이름이 모델을 새로 학습했다는 뜻은 아니다. 이번 연동은 REST 기반 실험·숫자 지표 기록이며 MLflow GenAI Trace를 자동 수집하는 설정은 추가하지 않았다. 상세 추적은 기존 LangSmith, 실행 단계 표시는 운영 페이지가 담당한다. Apache Airflow는 도입하지 않았다.

## 지표 범위

- 서버 상태, 가동 시간, 메모리에 있는 방 수, AI 실행 수와 대기 수.
- LangGraph 실제 콜백으로 수집한 기억 검색·생성·근거 검사·재검색·수정·기본 행동의 실행 순서와 시간.
- 프로세스 시작 이후 판단·재시도·기본 행동·실패 횟수. 실제 API 응답에 포함된 토큰만 합산하고 사용량 확인 호출 수를 함께 표시한다.
- 최근 최대 200회 판단의 P50/P95. 화면은 최근 30회만 보여준다. 단계를 최대 40개 보관하며 프롬프트·비공개 역할·발언·게임 ID를 수집하지 않는다.
- RSS는 현재값이 아닌 **프로세스 최대 사용량**이다. 캐시 상태는 설정값이며 적중률을 추정하지 않는다. 청구 금액도 추정하지 않는다.
- 프로세스 내 최근 기록은 재시작하면 초기화된다. MLflow는 별도 SQLite에 기록을 유지하지만 전송 성공한 숫자만 남는다.

토큰 캐시와 유효 기간이 있는 개인 판단은 기존 구현을 유지한다. 관측 콜백은 `set_config_context`로 요청별로 주입하므로 동결 평가에 사용한 `game/decision.py`는 수정하지 않았다. 기존 보류 평가 결과의 해시와 의미가 유지된다.

## MLflow 실패 처리

MLflow 클라이언트는 서버 시작 시 하나의 작업 스레드에서 생성해 재사용한다. 게임 스레드는 최대 64개 큐에 숫자만 넣고 즉시 진행한다. HTTP 제한 시간은 요청당 1.5초이며, 기록 실패 또는 큐 초과 시 누락 수를 늘린다. 무제한 재시도·메모리 축적을 하지 않는다. 연결은 약 10초 주기로 확인하며 종료 시 중지를 요청하고 최대 10초 동안 작업 스레드 종료를 기다린다.

이 방식은 게임 응답을 MLflow 장애와 분리하지만, 실패한 샘플을 영구 재전송하지 않으므로 지표가 빠질 수 있다. MLflow는 별도 프로세스와 DB, 패키지 설치 공간을 사용한다. 게임 프로세스 RSS에는 MLflow·MCP 프로세스 메모리가 포함되지 않는다. 장기 서비스에서는 보관 기간·삭제 정책, 관리자 인증, 다중 서버 집계가 필요하다.

## 행동 완료 기준과 병목 측정

`game/action_telemetry.py`는 AI 대기열 진입부터 `Game.submit`의 규칙 검사·상태 적용과 SQLite 저장 완료까지를 별도로 추적한다. 생성이 끝났어도 게임 규칙 검사나 DB 저장이 실패하면 행동 완료로 세지 않는다. 큐에서 실패·취소되어 모델을 호출하지 않은 경우도 분모에 포함한다. 실행 중인 행동은 종료되기 전까지 완료율 분모에서 제외한다.

- `completed`: 게임 적용과 저장이 모두 완료됨. 기본 행동 대체도 포함한다.
- `regular_completed` / `fallback_completed`: 일반 행동과 기본 행동 대체를 구분한다. 일반 행동도 모든 자연어 주장이 사실이라는 보증은 아니다.
- `failed` / `cancelled`: 실패와 취소, 당시 구간을 기록한다. 오류 원문과 비공개 게임 정보는 보관하지 않는다.
- `applied` / `persisted`: 게임 메모리 적용과 DB 저장을 구분한다. 저장 실패 때는 적용됐지만 저장되지 않은 상태가 표시될 수 있다. 이후 예외 처리의 별도 저장 성공을 최초 행동 성공으로 소급하지 않는다.
- 구간: 실행 대기 → AI 판단(검색·생성·검증 포함) → 방 잠금 대기 → 게임 적용 → 이력·사용량 정리 → DB 저장.

전체 시간에는 서버 시작·방별 클라이언트 초기화와 최초 관측 생성, 브라우저 전송·화면 표시가 포함되지 않는다. 사용자 체감 지연 전체로 발표하지 않는다. AI 판단 내부 구간은 기존 LangGraph 흐름을 함께 확인한다. 구간 비중은 최근 종료 최대 200건의 합산 시간 비중으로, 동시 실행 시 벽시계 시간 비중과 다르다.

완료 지연 P50/P95는 최근 종료 최대 200건 중 저장 완료 건만으로 계산한다. 실패·취소는 완료 지연에서 제외하므로 **완료율·실패 수를 반드시 함께 읽어야 한다**. 화면에는 해당 완료 표본 수를 표시한다. 누적 완료율·토큰 지표는 프로세스 시작 이후 값이다.

`known_tokens_per_completed_action`은 **종료된 모든 행동에서 확인 가능한 입력+출력 토큰 / 반영 완료 건수**다. 실패·취소에 소비된 토큰도 분자에 포함한다. 사용량 확인 호출 수/전체 호출 수를 같이 표시하며, 누락 사용량이나 청구 금액은 추정하지 않는다. 완료가 없거나 확인 가능한 사용량이 없으면 값은 null이다. 기본 행동 반영도 분모에 포함하므로 품질 지표와 구별한다.

MLflow에는 서버 행동당 하나의 샘플로 기존 판단 지표와 `action_*` 지표를 함께 전송한다. 큐 단계에서 끝난 행동에는 판단 지표가 없다. 독립적인 판단 점검은 기존 판단 지표만 기록한다. `action_count`가 있는 기록만 행동 표본이며, `seconds`는 판단 시간, `action_seconds`는 서버 행동 전체 시간이다. 연결 실패 시 기존 유한 큐·누락 정책을 유지한다.

## 같은 입력의 동시 실행 비교

```sh
.venv/bin/python -m game.benchmark_actions
```

4개 방에서 동일한 관측과 규칙봇 출력을 사용하고 동시 실행 수만 1/2로 바꾼다. 실제 그래프·로컬 검색·게임 적용·임시 SQLite 저장을 통과하며, 생성마다 40ms 대기를 주입한다. 각각 3회, 새로운 프로세스에서 순서를 번갈아 실행한다. 실제 OpenAI 지연·비용·답변 품질 비교가 아니며 외부 API 호출은 0회다. 입력과 적용 행동 해시를 대조한다.

[행동 완료 비교 결과](../reports/action-runtime-v1.md)와 [원시 수치](../reports/action-runtime-v1.json)를 참고한다. 운영 동시 실행 설정은 자동으로 바꾸지 않는다. 더 높은 동시성은 외부 API 제한·순간 메모리·MCP의 직렬 검색과 충돌할 수 있으므로 실제 부하 측정이 필요하다. 기존 [캐시·개인 판단 증분 처리 실험](../reports/runtime-optimization-v1.json)과는 다른 실험이다.

## 이번 보완 검증 결과
