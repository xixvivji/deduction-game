# AI 재검색·MCP 복구 및 자동 검사

G075 김지원 · 2026-10-22

이번 변경은 게임 규칙이나 그래픽을 추가하지 않는다. 실습 05~09의 조건 분기·검증·복구, 01~02의 공통 MCP 연결 수명, 13~14의 테스트·실측을 현재 AI 실행 경로에 적용했다.

## 재검색 정책

- 동일한 관측 안에서 주장, 인용, 검증 상태, 실제 선택된 이벤트 내용을 지문으로 비교한다. 기록 ID만 같아도 내용이 바뀌면 같은 실패로 취급하지 않는다.
- 처음 근거가 부족하면 기존처럼 검색 범위를 확장한다. 새로운 근거가 없더라도 모델이 피드백을 보고 한 번 수정할 기회는 준다.
- 같은 검색을 이미 했고 동일 실패가 반복되면 추가 생성·재검색을 멈추고 기존 안전한 기본 행동으로 끝낸다.
- 새로운 주장·인용·근거에는 제한된 수정 기회를 남긴다. 전체 생성 최대 3회, 확장 검색 최대 2회 한도는 유지한다.
- 구조화하지 않은 단정, 개인 판단 기록과의 모순 등은 검색보다 수정 경로로 보낸다. 수정 이후에도 검증을 통과해야 한다.
- 지문은 판단 요청 안에서만 보관한다. 다른 플레이어·게임·다음 턴으로 실패 판단을 공유하지 않는다.

한계: 같은 입력에서도 세 번째 생성에서 우연히 답을 고칠 모델의 기회를 줄일 수 있다. 따라서 호출 감소와 함께 기대 행동 일치·정상 응답 대체·기권 수를 확인한다. 개발용 합성 사례에서의 결과이며 일반 추리 능력 향상을 뜻하지 않는다.

## MCP 복구

서버 시작 시 생성한 관리자 한 개가 큐(최대 16개), 작업 스레드 한 개, stdio 연결 한 개를 소유한다. 정상 연결을 요청마다 새로 만들지 않는다.

- 사용 중 전송 실패 또는 유휴 상태 2초 간격 ping 실패를 감지하면 기존 연결을 정리하고 재연결한다.
- 연속 재연결은 2회까지 시도하고 실패하면 10초 냉각 기간을 둔다. 냉각 중 요청은 명확한 오류로 종료한다.
- 연결이 바뀔 때 서명용 비밀값과 capability를 새로 생성한다. 원래 요청자의 필터링된 관측으로 읽기 검색만 최대 한 번 재실행한다.
- 도구의 입력 거절은 연결 장애로 취급하지 않는다. 시간 초과·취소·종료된 Future에 늦은 결과를 적용하지 않는다.
- readiness는 MCP가 비정상일 때 503을 반환한다. 운영 화면에는 현재 상태, 대기열, 재연결 시도·복구 수, 최근 복구 시간을 표시한다.

복구가 제한 내 끝나면 진행 중 검색이 계속될 수 있다. 한도를 넘겨 이미 일시정지된 게임은 방장이 재개해야 한다. 자동 복구는 모델 요청이나 게임 행동을 재전송하는 기능이 아니다. ping 주기·도구 타임아웃에 따라 장애 감지 시간은 달라지고, 잦은 장애는 초기화 비용을 늘린다.

## 보존한 전후 결과

기준 코드: `d873595`. 각 JSON에 생성 시각, 입력 지문, 모델 설정, 실행 소스 지문을 기록했다. 기존 claim-guard 동결 평가와는 별도 버전이며 과거 결과를 현재 그래프의 새로운 평가로 바꾸지 않았다.

| 고정 응답 8개 상황 × 5회 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 모의 모델 생성 | 75 | 70 |
| 확장 재검색 | 25 | 20 |
| 기대 행동 일치 | 40/40 | 40/40 |
| 허용 사례의 기본 행동 대체 | 0 | 0 |
| 전체 기본 행동 대체 | 15 | 15 |
| 인용 접근 범위 위반 | 0 | 0 |

고정 응답은 구현한 제어 흐름의 회귀 검사다. 이 수치를 실제 API 호출·토큰 절감으로 설명하지 않는다. 로컬 그래프 실행 시간은 약 1ms대로, 측정 잡음·동시 작업의 영향을 받으며 모델 응답 시간 개선 근거로 사용하지 않는다.

실제 모델은 수정 전후 각각 같은 합성 투표 상황 8개를 별도로 실행했다. API 호출 **11→11회**, 재검색 **3→3회**, 기대 투표·기권 일치 **8/8→8/8**이었다. 평균 전체 판단 시간은 **1.728→1.723초**, 입력 토큰 **22,973→22,968**, 출력 토큰 **698→762**였다. 현재 표본에서는 호출·입력 비용 감소 효과를 확인하지 못했다. 모델 출력과 실행 시점이 달라 인과적 성능 향상으로 해석할 수 없고, 8건의 P95는 사실상 최대값이므로 안정적인 서비스 SLO도 아니다. 발언 전체의 오차단율·승률·요금은 평가하지 않았다.

별도 평가용 MCP 하위 프로세스를 실제 종료한 3회 시험은 **5초 관찰 창 내 복구 0/3→3/3**, 성공 시험의 평균 복구 시간 **약 0.60초**였다. 운영 중 게임 서버는 종료하지 않았다. 보고서의 실패 요청 수는 0.1초 간격 재확인 방식에 의존하므로 실제 사용자 오류율로 해석하지 않는다. 수정 전 미복구 시간은 `null`이며 0초로 계산하지 않는다.

## 실행과 화면

```bash
# 유료 모델 호출 없이 고정 응답 + 격리된 MCP 장애 시험
.venv/bin/python -m tools.reliability_probe --faults --output reports/reliability-after-v1.json

# 실제 모델 비교의 After만 갱신: .env의 cloud provider, 8상황, 최대 24회 생성
.venv/bin/python -m tools.reliability_probe --live --repeats 1 --output reports/reliability-live-after-v1.json

# CI와 동일한 오프라인 검사, API 키 사용 안 함
.venv/bin/python -m tools.run_checks --output reports/reliability-checks-v1.json
```

Before 파일은 현재 코드로 덮어쓰지 않는다. 재현하려면 기준 커밋의 `game/`을 별도 임시 체크아웃에 추출하고, 같은 평가 스크립트와 잠금 의존성으로 실행한다. 입력·모델 설정이 다르면 운영 페이지는 비교 불가로 표시한다. 코드가 측정 후 바뀌면 이전 결과임을 표시하며, 미측정 수치를 0으로 만들지 않는다.

`/ops`의 **AI 재검색 · MCP 복구 개선 전후**에서 고정 응답·실제 API·장애 시험·품질 검사 결과를 구분해 확인한다. 현재 서버의 실시간 사용량과 별개다. 로컬 실행은 보고서 파일 변경을 다음 갱신 시 읽는다. Docker는 보고서를 이미지에 포함하므로 새 결과 반영 시 `docker compose up -d --build --no-deps game`이 필요하다. 코드·데이터 변경 없이 평가만 다시 실행해도 유료 호출이 발생하는 버튼은 제공하지 않는다.

## GitHub Actions

`.github/workflows/quality.yml`은 `feature/**`, `develop`, `main` push와 통합 브랜치 PR에서 Python 단위·통합 검사, JavaScript 검사, 운영 화면 문법 검사를 실행한다. 실제 MCP 연결·종료·복구 시험을 포함하되 외부 모델 API는 호출하지 않는다. 실패하면 작업이 실패하고 결과 JSON·로그를 14일 보관한다. 로컬 검사 결과는 원격 CI 통과와 명확히 구분한다.

현재 로컬 최종 검사: Python 233개, JavaScript 6개 통과. CI 성공은 테스트에 포함된 경로의 근거이며 모든 장애·모델 출력의 정확성을 보장하지 않는다. 브랜치 보호에서 검사 필수화를 설정하는 것은 별도 저장소 운영 정책이다.
