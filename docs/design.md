# 게임 및 멀티플레이 구조 초안

## 목표와 범위

턴제 낮/밤 토론에 장소 선택과 제한된 목격 정보를 결합한다. 기존 게임의 캐릭터·맵·문구를 복제하지 않고 자체 규칙과 설정을 만든다.

기본 구성은 사람 1명과 AI 6명, 총 7명이다. 역할은 늑대 2명, 조사자 1명, 의사 1명, 시민 3명이다. 5인(늑대 1명)도 테스트용으로 지원한다. 사람과 AI 모두 어떤 역할이든 배정될 수 있다. 사람/AI는 조작 주체이며 시민/늑대는 승리 진영이다. 초기 수치는 플레이 테스트 후 조정한다.

실시간 이동, 음성 채팅, 복잡한 역할, 랭킹은 첫 범위에서 제외한다. 공개 텍스트 토론, 투표, 밤 행동, 게임 결과와 근거 회고를 구현한다.

## 주요 기능

1. 게임 방 생성 및 사람/AI 참가자 구성
2. 개인 역할·허용 정보에 따른 AI 발언과 투표
3. 낮 토론·투표 및 밤 행동을 처리하는 규칙 엔진
4. 장소 선택과 제한된 목격 정보에 따른 알리바이 추리
5. 게임 종료 후 역할 공개와 발언·행동 기록 회고

## 진행 단계

LOBBY → ROLE_ASSIGNMENT → NIGHT_ACTION → NIGHT_RESOLUTION → DAY_DISCUSSION → DAY_VOTE → VOTE_RESOLUTION → 다음 NIGHT_ACTION 또는 FINISHED.

첫 밤에는 공격 없이 조사·목격만 처리하여 플레이어가 첫 토론에 참여할 수 있게 한다. 이후 밤에는 공격을 허용한다. 매 밤/투표 해결 직후 승패를 확인한다. 늑대가 제거되면 시민 승리, 살아 있는 늑대 수가 나머지 생존자 수 이상이면 늑대 승리다. 최대 8일에서 미결이면 무승부로 종료한다.

낮에는 생존자별 제한된 발언 기회를 제공한다. 자유 무한 대화 대신 2회 발언 라운드를 초기 기준으로 사용한다. 투표는 자기 자신을 제외한 생존자 또는 기권을 선택한다. 최다 득표 동률 또는 기권이 최다이면 추방하지 않는다. 세부 UX와 제한 시간은 구현 시 확정한다.

## 밤 행동과 목격 — 초기 규칙 제안

장소는 광장·창고·숲길 3곳이다. 모든 생존자는 장소를 고른다. 조사자는 생존자 한 명의 진영을 조사하고, 늑대는 두 번째 밤부터 자신을 제외한 생존자 한 명을 공격 대상으로 선택한다. 장소 선택은 첫 버전에서 공격/조사의 거리 조건으로 사용하지 않는다.

목격은 같은 장소에 있던 다른 참가자 중 최대 한 명의 신원과 장소를 알려준다. 목격자가 없을 수 있으며, 동선 전체나 범행 여부를 증명하지 않는다. 서버가 실제 장소 선택으로부터 생성하고 AI가 사실을 창작하지 않는다. 이 규칙의 추리 재미와 공격/장소의 연계 여부는 플레이 테스트 후 조정한다.

밤 행동은 모두 확정하거나 기한이 끝난 후 한 번에 해결한다. 정보 생성 → 공격 처리 → 생존자에게 개인 결과 전달 → 공개 밤 결과 순서로 처리한다. 사망자는 이후 발언·투표·행동에 참여하지 않는다. 기한 내 미제출 시 기본 장소 선택, 특수 능력 미사용으로 처리한다.

## 멀티플레이를 위한 구조

게임 서버가 유일한 상태 원본이다. 클라이언트와 LLM은 행동을 제안하며, 서버가 단계·생존·권한·대상 유효성을 검증하고 결과를 확정한다.

- GameRoom: room_id, phase, round, state_version, deadline, ruleset_version
- Participant: participant_id, room_id, controller_type(human/ai), role, alive
- Command: command_id, participant_id, expected_version, type, payload
- GameEvent: event_id, sequence, visibility, recipient_ids, type, payload
- Observation: 참가자별로 공개 정보와 허용된 개인 정보만 조합한 모델/화면 입력

사람과 AI는 같은 명령 검증 경로를 사용한다. 조작 주체만 HumanController와 AIController로 분리한다. 단일 플레이도 항상 방 안에서 진행한다. 기본 7인 규칙에서 멀티는 사람 2~4명과 남은 AI로 확장한다. 총인원 확대는 별도 역할 균형 조정이 필요하다.

명령 중복은 command_id로 제거하고, 방 단위 순차 처리와 버전 확인으로 경합을 막는다. 재접속은 인증된 참가자 세션과 마지막 이벤트 번호를 기반으로 허용된 상태를 복구한다. room_id나 participant_id만으로 비공개 정보를 조회할 수 없게 한다. 연결 끊김 시 해당 턴의 기본 행동을 적용하고, AI 자동 대체는 후속 기능으로 둔다.

WebSocket으로 공개/개인 이벤트를 전달한다. 사망한 사람은 종료까지 공개 정보만 관전한다. 전체 역할과 행동 기록은 게임 종료 후 공개한다. 서버 전체 상태를 브라우저에 보내고 UI에서 숨기는 방식을 사용하지 않는다.

## AI와 공유 자원

모델 클라이언트와 그래프 정의는 재사용하고, 방/참가자별 기억과 실행 상태는 분리한다. AI에게 전체 역할표를 제공하지 않는다. 시민의 실수와 늑대의 의도적인 게임 내 거짓말을 구분한다.

AI 실행 흐름: 허용 정보 구성 → 관련 기억 조회 → 발언 또는 행동 생성 → 스키마 검증 → 게임 규칙 검증 → 이벤트 기록. 파싱/형식 재시도는 최대 1회, 실패 시 발언 건너뛰기 또는 기본 행동으로 처리한다. 모델 호출 동시성에 제한을 둔다.

늑대의 발언이 거짓이라는 이유로 거부하지 않는다. 서버 검증은 권한과 행동 유효성을 담당한다. 시스템 차원의 비공개 정보 유출은 입력 경계로 예방한다. 플레이어의 발언은 비신뢰 게임 데이터로 취급한다.

## 기술 적용

FastAPI + WebSocket, Vue, LangGraph, Ollama를 기본 후보로 둔다. SQLite에 게임 이벤트와 실행 기록을 저장하고 의존성 주입으로 모델/저장소를 교체한다. LangSmith 추적에 개인 역할이 포함될 수 있으므로 공개 화면과 분리한다.

RAG는 긴 토론에서 관련 발언·투표 기록을 조회하는 용도로 검증한다. 짧은 게임에서는 전체 허용 기록 전달을 먼저 기준선으로 삼는다. 비공개 접근 필터를 검색 이전에 적용한다. MCP는 허용 기록 조회 같은 도구 분리의 필요성을 확인한 뒤 도입하며 처음부터 필수로 두지 않는다.

## 비교 평가

고정된 게임 상태·역할·질문 세트에서 다음을 비교한다.

- 전체 허용 기록 vs 관련 기록 검색: 토큰, 지연시간, 기록 회상 정확도
- 자유 출력 vs 구조화 출력+서버 검증: 유효 행동률, 잘못된 행동 실행률, 재시도 횟수
- 정보 경계: 권한 없는 사실이 모델 입력/화면에 포함되는지 결정적 테스트
- 발언 평가: 근거 없는 주장을 측정하되, 늑대의 허용된 기만과 구분

전체 게임 승률은 역할/인원/모델/반복 수에 영향을 받으므로 보조 지표로 사용한다. 정답을 우연히 맞힌 것을 정보 유출로 단정하지 않는다. 초기 데모에서는 성능 수치를 미리 만들어 넣지 않는다.

## 구현 순서

1. 모델 없이 역할 배정·단계 전환·행동 검증·승패를 테스트한다.
2. 사람 1명 + AI 6명의 텍스트 게임을 연결한다.
3. 장소·목격 및 게임 종료 회고 화면을 구현한다.
4. 다중 브라우저 참가·개인 이벤트·재접속을 검증한다.
5. 기억 검색 및 모델 호출 개선 전후를 측정한다.

멀티 확장을 고려한 설계와 실제 멀티 구현 완료를 구분한다. 현재 규칙 엔진, 제공자 선택, LangGraph 기억 검색, Vue 브라우저 플레이, 단일 서버 멀티 및 SQLite 재개까지 구현되어 있다.

## 7인 늑대 공격 규칙

늑대는 동료 신원을 개인 관측으로 제공받는다. 생존 늑대 전원이 같은 비동료 대상을 선택해야 밤 공격 1건이 성립한다. 불일치나 기권이 있으면 공격하지 않는다. 두 번째 밤부터 살아 있는 늑대가 한 번씩 공격 제안을 공유하는 비밀 협의 단계를 구현했다. 합의가 보장되는 것은 아니며 최종 선택이 다르면 공격하지 않는다.
